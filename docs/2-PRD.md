# Team WBS PRD

## 1. 개요
WBS(업무) 기반 일정 및 작업시간 관리 웹 서비스. 상세 규칙/데이터 모델은 [1-domain-definition.md](./1-domain-definition.md) 참고.

## 2. 목표 / 성공지표
- 목표: 팀원 개인/전체의 WBS를 한 곳에서 캘린더로 관리
- 성공지표: 별도 성과 지표(KPI) 없음 — 사내 사용 도구로, WBS 관리 활용도·사용자 만족도로 정성 평가

## 3. 타겟 사용자
- 초기 10명, 이후 확대 시 최대 100명 규모
- 직무: 서비스기획자, 데이터엔지니어, AI엔지니어, 개발자 등 IT 직무 인원

## 4. 범위 (MVP)

### 포함
- 회원가입/로그인/탈퇴
- WBS(업무) 등록/수정/삭제 (본인 게시글, 관리자 예외 포함) — 캘린더/생성 화면 우선 개발
  - 관리자 예외는 **별도 화면 없이** 기존 캘린더/상세패널에서 권한만 다르게 동작(타인 게시글 등록/수정, 상태를 DONE으로 변경). 최초 관리자 계정은 DB 시드 데이터로 직접 생성(관리자 계정 관리 UI는 2차)
- 캘린더에서 막대 드래그로 기간 지정 → 우측 상세패널에서 상세 작성
- 상태값(해야할일/진행중/QA/해결됨/완료) 관리
- 일자별 1시간 단위 시간 할당 및 합산
- 내 WBS관리 탭 (상태별 현황)

### 제외 (2차 이후)
- 관리자 전용 화면(회원 관리, 게시글 집계 대시보드) — 관리자 예외 로직 자체는 MVP에 포함, 이를 위한 별도 UI만 2차
- 상태변경/마감일 알림(Teams 연동)
- 회원별 주간 할당시간·수행 프로젝트 수 집계 (도메인정의서 5절) — 내 WBS관리 탭의 상태별 현황까지만 MVP, 집계 통계는 2차

## 5. 화면 목록

| 화면 | 설명 |
|---|---|
| 로그인 | 이메일/비밀번호 로그인, 회원가입 링크 |
| 회원가입 | 이메일(형식 검증)/비밀번호/이름 입력 |
| 캘린더 메인 | 5주 뷰(오늘 포함 주 정중앙), WBS 막대 드래그로 생성/기간 조정 |
| 게시글 상세패널 | 캘린더에서 WBS 선택 시 우측에 노출. 제목/내용/담당자/시작일/종료일/일자별 수행시간 입력. 관리자 접속 시 타인 게시글도 동일 패널에서 등록/수정 가능 |
| 내 WBS관리 탭 | 상태값별 내 WBS 목록 (우측 하단) |
| 마이페이지 | 탈퇴 처리 |
| 관리자 화면 (2차) | 회원 관리, 게시글 집계 대시보드 |

## 6. 플랫폼
- 웹 애플리케이션 우선 개발
- 반응형 웹 UI 필수 적용 (별도 모바일 앱/전용 UI 없음, 모바일은 반응형으로만 대응)

## 7. 일정
- 7일 내 핵심 기능 완성

| 일차 | 작업 |
|---|---|
| 1일차 | DB 스키마(회원 token_version 포함), 인증(회원가입/로그인/탈퇴, JWT access/refresh 발급·재발급·폐기) |
| 2~3일차 | 캘린더 메인(5주 뷰, 막대 드래그 생성/기간조정) — 난이도 높아 버퍼 포함 |
| 4일차 | 게시글 상세패널(입력/수정), 일자별 시간 할당·합산 |
| 5일차 | 상태값 관리(권한별 전환), 관리자 예외 로직 |
| 6일차 | 내 WBS관리 탭 |
| 7일차 | 통합 테스트, 버그 수정 |

## 8. 알림
- 1차 범위 제외. 추후 상태변경/마감일 Teams 알림 검토.

## 9. 기술 스택
- Frontend: React 19, 전역상태관리 Zustand, 서버상태/통신 TanStack Query
- Backend: Node.js + Express, DB 드라이버 pg
- DB: PostgreSQL 17
- 인증: JWT 기반 (Access Token + Refresh Token). Access Token은 짧은 만료(예: 15분), Refresh Token은 긴 만료(예: 14일)로 재발급. 폐기는 별도 토큰 테이블 없이 회원 테이블의 `token_version`을 로그아웃/탈퇴 시 증가시켜 처리(도메인정의서 6절 참고)

## 10. 프로젝트 관리
- 팀 구성: 1인 개발
- 예산: 1인 개발 규모에 준함

## 11. 사용자 시나리오
로그인 → 일정 확인 → 일정 등록 → 상세 내용 작성 → 등록 확인 → 내 WBS관리 → 내용 수정 → 유지/로그아웃

## 12. 접근성
- 이번 범위에서 고려하지 않음 (out-of-scope)
